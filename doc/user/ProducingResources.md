# Producing Resources

This guide explains how to declare and produce resources on demand in
scout-essentials using the Resource module. You'll learn about claims,
production types, and how resources integrate with Path resolution.

## When to use this

- You need files that are created on first access (downloaded, generated,
  or computed).
- You want to declare where a resource comes from and let the framework
  produce it automatically.
- You're building a package that bundles data files, configurations, or
  tools that may need to be downloaded or built.

## Concepts

### Resources

A resource is a file or directory that can be produced on demand. You
"claim" a resource by specifying how it should be created. When something
tries to access the resource (via `Path.find`, `Open.read`, etc.), the
production logic runs automatically.

```ruby
module MyApp
  extend Resource
  self.pkgdir = 'myapp'

  # Claim: the file config.yaml contains this string
  claim self.config.yaml, :string, "default: true\n"
end

# Access triggers production automatically
config = MyApp.config.yaml.produce
content = Open.read(config)
```

### Claims

A claim registers how to create a specific logical path. The `type`
determines how the content is produced:

| Type | What happens |
|------|-------------|
| `:string` | The provided string is written to the file |
| `:proc` | The block/proc is called; its return value is saved |
| `:url` | The URL is downloaded and saved |
| `:rake` | A Rakefile is executed to build the target |
| `:install` | A software installer is run |

### Production

Production is the process of creating the file. It is idempotent — if the
file already exists, production is skipped. Production is atomic — the file
is written to a temporary location and moved into place.

## Basic usage

### Declaring resources

```ruby
module DataFiles
  extend Resource

  # Static string content
  claim self.data.config, :string, "key=value\n"

  # Generated by a proc
  claim self.data.generated do
    compute_config_from_params
  end

  # Downloaded from a URL
  claim self.data.reference, :url, "https://example.com/ref.fa"
end
```

### Producing a resource

```ruby
# Explicit production
path = DataFiles.data.config.produce
# => "/path/to/data/config" (file now exists)

# Implicit production via Open
content = Open.read(DataFiles.data.config)
# Resource is produced automatically if it doesn't exist
```

### Checking if a resource exists

```ruby
path = DataFiles.data.config
path.exists?               # => true if file exists
path.exists?(produce: true) # => triggers production, then checks
```

## Claim types

### String content

```ruby
claim self.etc.version, :string, "1.0.0\n"
```

### Proc-generated content

```ruby
claim self.data.summary, :proc do
  data = load_source_data
  summarize(data)
end
```

The proc can return a String, an IO, or an Array. If the proc accepts an
argument (arity 1), it receives the target filename:

```ruby
claim self.data.report, :proc do |filename|
  Open.write(filename, generate_report)
  nil  # already written; return nil
end
```

### URL download

```ruby
claim self.data.genome, :url, "https://example.com/genome.fa.gz"
```

The file is downloaded on first access. Subsequent accesses use the cached
file.

### Rake-based production

```ruby
# Declare a Rakefile as a resource
claim self.Rakefile, :string, <<~RAKE
  file 'output.txt' do |t|
    Open.write(t.name, "generated")
  end
RAKE

# Claim a target produced by the Rakefile
claim self.output, :rake, self.Rakefile
```

## Integration with Path

Resource extends the Path system. Resource-backed paths can be found,
produced, and opened like regular paths:

```ruby
# Path resolution with production
path = MyResource.data.file

path.find            # finds existing file (or nil if not produced)
path.produce         # produces if needed, returns path
path.exists?         # checks existence
Open.read(path)      # reads (may trigger production)
```

### Resource as a module

A Resource module represents a package or collection. The `pkgdir` sets the
package directory used in path resolution:

```ruby
module GenomicsDB
  extend Resource
  self.pkgdir = 'genomics'

  # Paths resolve under the genomics package directory
  claim self.ref.hg38, :url, "https://..."
end
```

## Synchronizing resources

Resources can be synchronized (rsync) between locations:

```-resync
```ruby
# Sync from a source to target
GenomicsDB.ref.hg38.sync(source_dir)
```

## Common mistakes

### Forgetting to extend Resource

```ruby
# WRONG: claim is not available without extend Resource
module MyData
  claim self.file, :string, "content"  # NoMethodError
end

# RIGHT
module MyData
  extend Resource
  claim self.file, :string, "content"
end
```

### Confusing find and produce

```ruby
# find: returns path if exists, nil otherwise (does NOT produce)
path = MyResource.data.file
path.find  # => nil if not yet produced

# produce: creates if missing, returns path
path.produce  # => path (file now exists)
```

### Production failing silently

If a proc returns nil without writing a file, the resource is considered
"not produced." Make sure your proc either returns content (String, IO) or
writes to the target filename explicitly.
